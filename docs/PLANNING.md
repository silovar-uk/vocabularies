# Vocabularies — Planning the Planning

## 0. この文書の目的

このプロジェクトでは、画面から考え始めない。

まず「どう考えれば、この語彙集の価値を損なわずに設計できるか」を決め、その順序に沿ってコンテンツ・情報構造・体験・UIを作る。

---

## 1. Product definition

### 仮の一文定義

> うまく言葉にできない感覚から、より精密な概念・専門語へたどり着くための語彙集。

### このプロダクトが兼ねるもの

- 専門用語辞典
- 感覚の翻訳機
- 言語化支援ツール
- 発見型学習ツール
- 個人的な知識コレクション

### 優先順位

辞書としての網羅性よりも、**言葉を知ったことで世界の差が見えるようになること**を優先する。

---

## 2. Planning sequence

### Phase 1 — 言葉に困った実例を集める

最初に専門用語を集めない。

先に、日常の「うまく言えない」を集める。

例：

- なんかこのUIうるさい
- この余白、変
- 論文っぽくない
- この歌声、冷たい
- この写真、映画っぽい
- この会話、距離が遠い
- この企画、悪くないけど芯がない

この層を `feelings / vague expressions` として保存し、あとから専門語へ接続する。

### Phase 2 — 探索する分野を広げる

分類を確定するのではなく、まず探索範囲を作る。

- Design / UI / Web
- Graphic Design
- Architecture / Space
- Photography
- Film
- Art
- Music / Singing / Sound
- Writing
- Literature
- Linguistics
- Psychology
- Cognition
- Emotion
- Sociology
- Philosophy
- Marketing
- Communication
- Games
- Sports
- Body / Movement

### Phase 3 — 掲載基準を決める

優先する語：

- 「なんか」を細分化できる
- 実際の会話・仕事・鑑賞で使える
- 別分野へつながる
- 知ったあとに見え方が変わる
- 専門家の暗号だけで終わらない

優先度を下げる語：

- 定義を知っても観察や判断が変わらない
- 極端に狭い領域でしか使わない
- 既存語との差がほぼ説明できない

### Phase 4 — 1語のデータ構造を固める

初期schema：

- `id`
- `term`
- `ja`
- `fields`
- `one_liner`
- `description`
- `feelings`
- `before`
- `after`
- `related`
- `opposites`
- `sources`
- `status`

必要に応じて後から、理解度・お気に入り・自分用メモを追加する。

### Phase 5 — 入口を設計する

入口は3つ。

1. 感覚から探す
2. 分野から探す
3. 用語から探す

ただし同列に扱わない。

**主役：感覚から探す**  
補助：分野 / 用語検索

### Phase 6 — 感覚語のtaxonomyを作る

例：

#### 見た目
- うるさい
- 重い
- 軽い
- 安っぽい
- 上品
- 落ち着く

#### 音
- 暖かい
- 冷たい
- 太い
- 乾いている
- 浮遊感

#### 文章
- 固い
- くどい
- テンポが悪い
- 余韻がある

#### 人間関係・感情
- 距離がある
- 気まずい
- 安心する
- 緊張する

ここから複数の専門語へリンクする。

### Phase 7 — CategoryよりRelationshipを重視する

この語彙集はフォルダ型だけにしない。

例：`Rhythm`

- Visual Rhythm
- Prosody
- Groove
- Pacing
- Repetition
- Cadence

「デザインを見ていたら音楽へ飛ぶ」ような横断を意図的に作る。

### Phase 8 — 学習ループを設計する

読むだけで終わらせず、最終的には以下を回せるようにする。

> 知る → 見つける → 使う

候補：

- 今日この概念を探してみる
- 自分の言葉で説明する
- 最近これを感じた場面を書く
- 似た概念との違いを見る
- 今日の3語

### Phase 9 — 実データで検証する

UIを完成させる前に20〜30語を入れる。

実データを並べて、

- 何を一覧に見せるべきか
- 詳細ページに何が必要か
- 感覚語検索が機能するか
- 関連語が役に立つか

を確認する。

### Phase 10 — UIを磨く

ここで初めて本格的に、

- トップ
- 検索
- カード
- 詳細
- 関連語
- フィルター
- スマホUI

を調整する。

設計順は常に：

> 概念 → データ → 関係 → 体験 → UI

## 3. Planning rounds

### Round 1 — 思想
- 何のための語彙集か
- 何を載せるか / 載せないか
- 成功とは何か

### Round 2 — 語彙
- 分野
- 掲載基準
- 初期100語候補

### Round 3 — 構造
- 1語のschema
- 感覚語
- タグ
- 関連語
- 反対語 / 混同語

### Round 4 — 体験
- 感覚から探す
- 分野から探す
- 用語検索
- 偶然の発見
- 学習ループ

### Round 5 — UI / Implementation
- ワイヤーフレーム
- デザインシステム
- スマホ最適化
- GitHub Pages
- データ更新方法
